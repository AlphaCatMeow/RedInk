# 解决图片预览与编辑界面不一致问题

用户指出在编辑界面（大纲页）生成的图片与预览界面（结果页）不一致。这主要是因为：
1. 编辑界面单张生成图片后，没有同步更新到后端的历史记录，导致刷新或跳转后数据丢失。
2. 点击“开始生成”进入生成界面时，Store 会重置所有图片状态，导致已生成的图片被丢弃并重新生成。
3. 结果页的重绘功能同样没有同步更新历史记录。

我们将通过以下步骤解决这些问题，确保图片状态在所有页面保持一致且持久化。

## 修改计划

### 1. 前端 Store 逻辑优化
**文件**: `frontend/src/stores/generator.ts`
- 修改 `startGeneration` 方法：不再强制重置所有图片。
- 逻辑变更：初始化时检查 `store.images`，保留状态为 `done` 且 URL 有效的图片，只重置未生成或失败的图片状态。

### 2. 大纲视图 (OutlineView) 完善
**文件**: `frontend/src/views/OutlineView.vue`
- 修改 `generateSingleImage` 方法：
  - 在图片生成成功并更新 Store 后，立即调用 `updateHistory` API。
  - 构建完整的 `generated` 文件名列表（合并现有图片），将最新状态同步到后端数据库。
  - 这样确保用户离开页面或刷新后，最新生成的图片依然存在。

### 3. 生成视图 (GenerateView) 增量生成
**文件**: `frontend/src/views/GenerateView.vue`
- 修改 `onMounted` 逻辑：
  - 计算需要生成的页面列表 `pagesToGenerate`（排除已完成的）。
  - 如果所有页面都已生成，直接调用 `finishGeneration` 并跳转到结果页。
  - 如果有待生成页面，只将这些页面传递给 `generateImagesPost` 进行增量生成。
- 修改 `onFinish` 回调：
  - 更新历史记录时，不再仅依赖后端返回的（增量）图片列表。
  - 改为遍历 `store.images`（包含已保留的和新生成的），构建完整的图片列表进行保存。

### 4. 结果视图 (ResultView) 同步修复
**文件**: `frontend/src/views/ResultView.vue`
- 修改 `handleRegenerate` 方法：
  - 与 `OutlineView` 类似，在重绘成功后，立即调用 `updateHistory` 同步最新状态到后端。

## 预期效果
1. **一致性**：无论在哪个页面生成图片，其他页面都能显示最新结果。
2. **持久化**：生成的图片会实时保存，刷新页面不会丢失。
3. **效率提升**：在编辑页生成满意的图片后，点击“开始生成”不会被覆盖，系统只会生成剩余的图片。
